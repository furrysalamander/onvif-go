# AGENTS.md — guidance for opencode and any codegen agent

This file tells opencode (and any other coding agent) everything it needs to
work effectively in this repository.

## Repository

`github.com/furrysalamander/onvif-go` — pure-Go ONVIF client + server library,
generated from vendored ONVIF WSDL/XSD schemas.

Go toolchain: **1.26+** (set in `go.mod`). Module path:
`github.com/furrysalamander/onvif-go`.

## Mandatory commands

Always run these after substantive changes and report the results:

```bash
go generate ./...            # regenerate code from vendored schemas
go vet ./...                 # static checks
go build ./...               # compile everything, including cmd/*
go test ./...                # run the test suite
                             # (use `go test -run TestGolden -update` to refresh golden files)
```

CI additionally runs `Makefile` targets `lint` (golangci-lint) and `check-gen`
(generation must be a no-op against committed output). **Never commit schema
drift** — if you modify schemas or the generator, regenerate and commit the
diff.

## Code style

- Match surrounding code. `gofmt` + `goimports` are non-negotiable; enforced by
  golangci-lint.
- **Do not add comments** unless the user asks. ONVIF spec references carried
  from `<xs:documentation>` are produced by the generator only.
- No emojis unless asked.
- Use `errors.Is`/`errors.As` for fault flow; do not sentinel-string compare.
- Pure Go only. New third-party deps require justification; prefer the
  standard library and `golang.org/x/...`.

## Project layout

```
cmd/
  onvifgen/      code generator — run via `go generate ./...` (see directives)
  onvif-cli/     ad-hoc CLI client
  mockcam/       mock ONVIF camera server (Phase 1+)

internal/
  catalog/       vendored ONVIF WSDL/XSD + OASIS/W3C support schemas (DO NOT edit generated)
  ws/            SOAP 1.2 envelope, fault model, addressing headers
  wsdiscovery/   WS-Discovery UDP multicast (Probe/ProbeMatch/Hello/Bye)
  wssecurity/    WS-Security UsernameToken (digest auth) outbound + inbound
  xmlns/         namespace URI registry

onvif/           public API
  schema/        GENERATED per-namespace type packages (tt/, tds/, trt/, tpe/, tev/, tis/)
  devicemgmt/     DeviceMgmt facade + generated op stubs
  media/ media2/ ptz/ events/ imaging/  ... same pattern
  client/        device discovery + transport + service routing
  testutil/      golden-file harness + mock-server fixture for round-trip tests

testdata/        golden XML per op, fixtures
```

## Generated code

- All output of `cmd/onvifgen` lives under `onvif/schema/` and per-service stub
  packages.
- Files begin with `// Code generated by onvifgen; DO NOT EDIT.`
- **Committed to git** on purpose — consumers can `go get` without running the
  generator, and PR diffs surface schema drift visibly.

## Testing strategy

- **Unit** per package (generated + hand-written).
- **Golden files** at `testdata/golden/`: request marshal, response demarshal,
  faults — refreshed with `go test -run TestGolden -update`.
- **Round-trip** in `onvif/testutil`: boots `mockcam` on `127.0.0.1:0`, runs the
  client at it, asserts typed equality + golden XML.
- **ODM validation** (manual checklist) against each release tag — see
  `docs/odm-validation.md` (created in M8).
